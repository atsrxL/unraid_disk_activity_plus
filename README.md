# Unraid Disk Activity Plus

A fork of [DerekChan65535/unraid-disk-activity](https://github.com/DerekChan65535/unraid-disk-activity) focused on conservative HDD wake attribution, wake history, power state, and live open-file visibility for Unraid 7.3+.

## Install

Paste this URL into **Unraid → Plugins → Install Plugin**:

```text
https://raw.githubusercontent.com/atsrxL/unraid_disk_activity_plus/main/disk.activity.plg
```

This fork intentionally keeps the internal plugin name `disk.activity`, so install it **instead of** the original Disk Activity plugin, not alongside it.

## UI

Open **Settings → User Utilities → Disk Activity Plus**.

The single plugin entry contains two tabs:

- **Open Files / Settings** — wake-tracker settings and a live list of regular files currently open on monitored HDD/ZFS storage.
- **Wake History** — physical STANDBY → ACTIVE history, per-disk wake counts, confirmed wake-source shares and Reset Wake Statistics.

The previous Dashboard Open Files tile was removed in 2026.08.21.5. Current open files remain available inside the plugin as a troubleshooting view without occupying Dashboard space.

## Attribution model

- **HIGH** — a unique fanotify process access was observed immediately before the first physical block-I/O change. This includes direct monitored-filesystem events and uniquely correlated Unraid `/mnt/user` or `/mnt/user0` events.
- **MEDIUM** — no HIGH event was available and exactly one process had a matching open descriptor at I/O onset.
- **UNKNOWN** — no safe userspace attribution, or multiple processes were plausible.

Only HIGH events are credited to named wake-source percentages. MEDIUM candidates remain visible in event history but are grouped as unknown in source statistics.

The `/mnt/user` correlation is specifically intended to improve Docker, SMB and other Unraid user-share workloads where the userspace access path does not match the underlying ZFS/physical mount path. It is promoted to HIGH only when one unique PID is observed inside the correlation window; ambiguous candidates stay UNKNOWN.

## Low-impact design

- The legacy Main-page Activity % column and its separate 2-second sampler daemon have been removed.
- `/proc/diskstats` is still sampled in RAM only to confirm the onset of real physical I/O for wake attribution.
- Current open files are generated by the wake monitor from `/proc/*/fd` into `/var/local/emhttp/disk_open_files.json` (RAM).
- Power state uses Unraid's cached `disks.ini` first; `smartctl -n standby` is only an Auto fallback.
- Ordinary access events are kept in RAM. Only wake events are persisted to `/boot/config/plugins/disk.activity/wake-history.jsonl`.
- Wake history is fixed at **60 days** and at most **5,000 events**.
- History append, prune, API reads and reset share one lock; pruning/reset use atomic replacement.

## Security and maintainability

- Reset Wake Statistics keeps the endpoint simple and broadly compatible while rejecting browser requests that are clearly cross-origin.
- Docker/Podman container inspection uses `fork`/`exec`, not shell interpolation.
- Container-name cache entries use TTLs and bounded eviction.
- The native monitor is maintained as one normal `disk_wake_monitor.c` translation unit and is built with `-Wall -Wextra -Werror`.
